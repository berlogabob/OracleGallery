# UX/UI Audit — Neje Oracle operator GUI (web, Maestro Chromium) — 2026-08-05

## Executive Summary
Release verdict: **NOT READY** (1 open severity-4). 39 findings after dedup (1 sev-4, 8 sev-3, 22 sev-2, 8 sev-1); task success rate 100% (2/2 flows). Top issues: (1) the FluidNC error toast exposes raw `IP:port` technicalities with no recovery action, is non-dismissible, and disappears on some tabs while the error persists; (2) operator-facing developer jargon ('Z up legacy') and inconsistent button system (5 differently styled primary actions); (3) no success feedback after action buttons (jog/home/start), so the operator cannot tell whether a command executed. Baseline taken mid-cleanup: the known duplicate-status clutter (7 facts × 18 sites) was being fixed in parallel (commits 47d8b99, 199f110, f691790) — the trend section reflects that.

## Background & Objectives
Operator control GUI for the Oracle pen-plotter exhibition (NiceGUI web app, dry-run mode, branch uxui-cleanup pre-dedup baseline). Audit triggered by a declutter initiative after a code inventory found heavy partial duplication. Screens 01–06: the six workspace tabs; screen 07: the embedded p5.js sketch page (captured post-restyle — static files serve live, so screen 07 reflects commit 199f110, not the true 'before').

## Methodology
Crawl: all 6 workspace tabs + sketch page (7/7 reachable screens). Flow suite: workspace_tab_crawl (13 steps), sketch_page_loads_controls (3 steps) — Maestro CLI (the MCP server held a dead ChromeDriver session; CLI fallback per skill field notes). Frameworks: Nielsen 10, UX laws (Fitts/Hick/Miller/Jakob), visual design + WCAG estimates, design-system consistency vs PAGE_STYLE tokens, five system states, ISO 9241-11/HEART. NOT covered: view hierarchies (web CLI limitation → measurements.json empty, all measurements are visual estimates), real print flow, file-upload dialogs, Flutter gallery (separate surface).

## Key Findings

### Severity 4
**F-001 · sev 4 · H9 · 03_tests.png** — Error toast displays raw technical details: 'FluidNC Telnet offline: 10.28.8.74:23; HTTP offline (timed out)'. An operator does not need to know the IP address, port number, or protocol layer. The error provides no actionable guidance on how to recover (e.g., 'Check controller network connection and try reconnecting'). Evidence: `screens/03_tests.png`. Recommendation: Rewrite error messages in plain language. Instead: 'Controller offline. Check that the device is powered on and connected to the network, then reconnect.' Remove technical details (IP, port, protocol names).

### Severity 3
**F-002 · sev 3 · H2 · 02_calibration.png** — Input fields labeled 'Z up legacy' and 'Z down legacy' expose developer terminology ('legacy') to the operator interface. An operator does not understand what 'legacy' means in this context or why it matters. The labels should describe the user action or device state. Evidence: `screens/02_calibration.png`. Recommendation: Rename to user-facing terms such as 'Z rise speed (legacy)' or 'Pen up delay' / 'Pen down delay' depending on actual function. Add a help icon with tooltip if legacy variants must coexist with newer ones.
**F-003 · sev 3 · H4 · 04_work.png** — Button styling is inconsistent across sections: Mac mini uploader uses black buttons (START, STOP), while Thermal printer section uses colored buttons (green CONNECT, PRINT LATEST). No visual hierarchy or pattern explanation. User cannot predict which action is primary or destructive. Evidence: `screens/04_work.png`. Recommendation: Establish a consistent button style hierarchy: primary actions (green), secondary (gray), destructive (red). Apply uniformly across all sections. Use color to signal intent, not randomly.
**F-004 · sev 3 · H1 · 05_exhibition.png** — Status displayed as 'OPERATOR PAUSED · STOPPED' and 'EXHIBITION · FluidNC MOTION' using dot notation without a legend or key. Operator must guess what the dots mean (separation? hierarchy?). The same dot notation is not used consistently elsewhere in the UI (compare to 'user 0 · idle 15'). Evidence: `screens/05_exhibition.png`. Recommendation: Use explicit labels: 'Print status: Operator paused (Stopped)' and 'Mode: Exhibition (FluidNC motion)'. Avoid ambiguous separators. If dot notation is needed, provide a legend on first use.
**F-005 · sev 3 · H10 · 07_sketch_page.png** — The sketch editor exposes interactive controls—a 'circles' dropdown, a slider for parameter adjustment, a 'mask' checkbox, and an '+ Add layer' button—with no tooltips, help text, labels, or documentation. A first-time user cannot understand what these controls do or how to use them effectively. Evidence: `screens/07_sketch_page.png`. Recommendation: Add tooltips or a help panel (?) explaining each control. Example: 'circles: Generator algorithm. Slider: Shape complexity (0–100). Mask: Restrict output to selected region. Add layer: Stack multiple generation rules.' Consider a quick-start modal on first visit.
**F-006 · sev 3 · DS-BTN-1 · 04 Work** — In 'System run' and 'Thermal printer' cards, NEW RUN, SCAN, and TEST RECEIPT render as plain bold black text with no fill, border, radius, or shadow — indistinguishable from static labels — while sibling actions in the same row (START SYSTEM, STOP SYSTEM, START, STOP, RESTART, STATUS, CONNECT, PRINT LATEST, PRINT SELECTED) are all filled rectangular buttons. Same 'action button' family rendered as a no-chrome text variant with zero affordance. Evidence: `screens/04_work.png`. Recommendation: Give every clickable action at least a ghost/tertiary treatment (border or underline + hover state) from the shared button helper; never ship a bare ui.button with no props as a peer of filled buttons.
**F-007 · sev 3 · DS-BTN-1 · 02 Calibration** — In 'Manual motion', Z UP / PEN UP, Z- / PEN DOWN, HOME X, and HOME Y render as plain bold text with no button chrome, directly below the jog pad's black filled square buttons (X-, Y+, Y-, X+) and the gold filled HOME ALL button. Critical machine-control actions (including Z-axis and per-axis homing) are visually unidentifiable as buttons. Evidence: `screens/02_calibration.png`. Recommendation: Style Z UP/PEN UP, Z-/PEN DOWN, HOME X, HOME Y with the same button treatment as the adjacent jog buttons (or an explicit secondary variant) so all manual-motion controls share one recognizable affordance.
**F-008 · sev 3 · DS-BTN-1 · 07 Sketch page (pre-restyle)** — Regenerate, Send to plotter, and + Add layer render as fully-rounded (pill) outline buttons — cream fill, thin tan border, rust bold text — a button family not used anywhere across the six operator-surface tabs, which use rectangular ~8-10px-radius filled buttons in black/green/gold. Confirms this surface predates the oracle-card / PAGE_STYLE restyle. Evidence: `screens/07_sketch_page.png`. Recommendation: Bring the generative sketch page's controls into the shared button component (rectangular radius, filled colors) before it ships alongside the restyled operator tabs, or clearly gate it as an isolated iframe surface with its own intentional system.
**F-009 · sev 3 · ST-SUCCESS · 02_calibration, 03_tests, 04_work, 05_exhibition** — Action buttons (jog/home, START TEST PRINT, START SYSTEM, START PRINT) have no confirmation toast, checkmark, loading state, or state change after click. User cannot confirm action executed successfully. Reference standard: 'Completed actions confirm (state change, toast, checkmark) — the user never wonders "did it work?"' Evidence: `screens/02_calibration.png, screens/03_tests.png, screens/04_work.png, screens/05_exhibition.png`. Recommendation: Add immediate feedback for action buttons: show loading state (spinner/disabled button) during action, then success toast on completion. Example flow: button click → 'Homing X...' (loading) → 'Homing complete' (toast).

### Severity 2
**F-010 · sev 2 · H1 · 03_tests.png** — A dark progress bar displays '0.08 / 0.00%' with no label, context, or title. Operator cannot determine what is being measured (progress? ratio? memory?), and the two numbers suggest a comparison but the meaning is opaque. Evidence: `screens/03_tests.png`. Recommendation: Add a clear label above or below the bar: 'Compilation progress: 0.08 / 0.00%' or 'Test execution: X of Y complete'. If the metric is rarely used, consider removing it to reduce visual clutter (H8).
**F-011 · sev 2 · H2 · 04_work.png** — The line 'Controlled through NEJE_MACMINI_AGENT_URL' uses technical environment variable naming. An operator does not need or want to know this implementation detail. It distracts from the actual control (START/STOP buttons). Evidence: `screens/04_work.png`. Recommendation: Remove or relocate this line to a developer/settings panel. Replace with user-facing text if needed: 'Manages asset transfer to the device' or omit entirely.
**F-012 · sev 2 · H6 · 05_exhibition.png** — Progress detail line reads '15/16 cells · user 0 · idle 15'. Without seeing the print grid or knowing what 'user 0' and 'idle 15' mean, the operator cannot assess print status. The notation requires domain knowledge not provided by the UI. Evidence: `screens/05_exhibition.png`. Recommendation: Use explicit language: 'Cells completed: 15 of 16. Current: user queue 0 (waiting 15 cells). Row 2 of 4.' Add a visual grid or timeline to contextualize the position and remaining work.
**F-013 · sev 2 · H7 · 07_sketch_page.png** — The close button (×) in the top right corner of the sketch editor is small (relative to the large canvas) and lacks visibility or discoverability. A user might not see it as an option to return to the main UI. Evidence: `screens/07_sketch_page.png`. Recommendation: Increase button size, or add a visual affordance (e.g., background circle, border). Alternatively, add a 'Back' or 'Close' text button alongside the ×. Ensure keyboard shortcut (ESC) is available and documented.
**F-014 · sev 2 · H10 · 04_work.png** — Help text for the Thermal printer section is truncated: 'Printer offline is a warning only; plotter and upload workflow c...' The sentence ends abruptly, leaving the operator without complete information about the printer's role or offline behavior. Evidence: `screens/04_work.png`. Recommendation: Complete the truncated sentence and reflow text to fit the container. Provide clear guidance: 'Printer offline is a warning only; the plotter will continue. Upload workflow captures prints as images.' Add a [?] help icon with full explanation.
**F-015 · sev 2 · LAW-FITTS-1 · 02_calibration** — The 'Step mm' and 'Feed' number input fields with adjacent dropdowns are visually small (estimated 45-55px width each) and closely spaced horizontally. Recommendation: Increase minimum input field width to 60-70px; add 12-16px horizontal padding between control groups (Step/Feed pair vs. directional buttons). **F-016 · sev 2 · LAW-FITTS-1 · 03_tests** — The 'SVG test draw' section has two number inputs (SVG X0, SVG Y0) that are compact and narrowly spaced (estimated 80-110px wide each). Measurement: visual estimate: ~100px input width, minimal vertical spacing (~12px) between X0 and Y0 fields. **F-017 · sev 2 · LAW-HICK-1 · 04_work** — The 'Thermal printer' section displays 5 action buttons in a single horizontal row (STATUS, CONNECT, PRINT LATEST, PRINT SELECTED, TEST RECEIPT). Recommendation: Restructure into action groups: primary actions (CONNECT, PRINT LATEST) above; secondary actions (STATUS, PRINT SELECTED, TEST RECEIPT) in a smaller button row below, or hide secondary actions behind a 'More' / 'Advanced' menu. Recommendation: Split into two logical groups: (1) 'Connection' group with URL input + CONNECT button; (2) 'Operations' group with START, PRINT LATEST, PRINT SELECTED in primary row and STATUS/TEST RECEIPT in secondary row. ## Recommendations
1. (sev-4) Rework the FluidNC offline toast: plain-language message, RETRY action, dismiss button, persistent-but-quiet indicator that stays consistent across tabs (F-001, plus the flows findings on dismissibility/consistency).
2. (sev-3) Add success feedback (notify/toast) to every action button — jog, home, start-print family.
